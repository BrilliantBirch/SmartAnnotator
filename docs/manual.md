## 1. 产品概述

VAI_E_SmartAnnotator 是一款基于深度学习模型的智能数据标注工具，面向计算机视觉数据集制备场景，提供两大核心功能：

| 功能 | 说明 |
|------|------|
| **自动标注** | 加载 ONNX / TensorRT 模型，对图片和视频批量推理，自动输出 LabelMe 格式标注文件，大幅降低人工标注成本 |
| **格式转换** | LabelMe（JSON）与 YOLO（TXT）标注格式双向转换，支持数据集划分与目录结构导出 |

支持的目标检测任务模式：

| 任务模式 | 自动标注 | 格式转换 |
|----------|----------|----------|
| 目标检测（DETECT） | 支持 | 支持 |
| 姿态估计（POSE） | 支持 | 支持 |
| 实例分割（SEGMENT） | 支持 | 支持 |

## 2. 系统要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows 10 / 11（64 位） |
| CPU 版 | 无特殊要求，4 GB 以上内存 |
| GPU 版 | NVIDIA 显卡 + 已安装显卡驱动（无需安装 CUDA Toolkit） |
| 磁盘空间 | 安装约 1 GB（GPU 版），输出目录预留足够空间 |

**GPU 版说明：**

- GPU 推理基于 TensorRT 引擎，仅需安装 NVIDIA 显卡驱动，无需单独安装 CUDA Toolkit 或 cuDNN。
- 首次使用 ONNX 模型时，程序会自动将其转换为 TensorRT engine（约需 10~30 分钟，视模型大小而定），转换结果保存在模型同目录下，之后可直接复用。
- 若系统未检测到 CUDA 环境，程序将自动禁用 GPU 选项并回退到 CPU 模式。

## 3. 安装与启动

### 3.1 安装器安装

1. 双击安装程序（如 `VAI_E_SmartAnnotator_Setup_GPU.exe`）。
2. 按向导提示选择安装目录，完成安装。
3. 从开始菜单或桌面快捷方式启动程序。

### 3.2 开发环境运行（源码）

```bash
conda create -n VAI_E_SmartAnnotator python=3.12.10
conda activate VAI_E_SmartAnnotator
pip install -r requirements.txt
python -m smart_annotator
```

## 4. 界面总览

程序启动后进入欢迎页，包含两个功能入口按钮：**格式转换** 与 **自动标注**。

- 窗口宽度较大时（≥ 768px）：左侧显示导航栏，可在功能页面间切换。
- 窗口宽度较小时（< 768px）：自动切换为底部标签栏。
- 任务运行期间导航会被临时禁用，防止切换页面中断任务。

## 5. 格式转换

### 5.1 基础设置

| 设置项 | 说明 |
|--------|------|
| 源格式 | 选择 LabelMe（JSON）或 YOLO（TXT），目标格式自动交叉锁定 |
| 任务类型 | 目标检测 / 姿态估计 / 实例分割 |
| 输入目录 | 待转换的标注文件与图片所在目录 |
| 输出目录 | 转换结果保存目录 |

选择输入目录后，页面下方会显示文件列表与图像预览，可点击文件预览核对内容。

### 5.2 高级设置（目标为 YOLO 时生效）

| 设置项 | 说明 |
|--------|------|
| 类别列表 | 手动添加/编辑/删除类别名称，顺序即类别 id（从 0 开始） |
| 关键点列表 | 仅姿态估计任务显示；关键点名称须以 `_point{序号}` 结尾（如 `nose_point0`） |
| 训练集比例 | 默认 0.8 |
| 验证集比例 | 默认 0.1 |
| 测试集比例 | 默认 0.1（三者之和应为 1.0） |
| 可视化标注结果 | 勾选后在输出目录生成标注可视化图片，便于核对 |
| 导出 YOLO 数据集目录结构 | 勾选后按 `images/`、`labels/` 结构导出并完成数据集划分 |

### 5.3 执行与监控

点击 **开始转换** 后：

- 进度条实时显示转换进度，日志面板输出详细处理信息。
- 点击 **停止** 可随时中断任务。
- 转换完成后，日志面板会提示输出目录位置。

### 5.4 配置导入/导出

- **导出配置：** 将当前页面所有设置保存为 JSON 文件，便于复用。
- **导入配置：** 载入之前导出的 JSON 配置，自动回填界面（兼容旧版配置文件的键名格式）。

## 6. 自动标注

### 6.1 运行设备

- **GPU（推荐）：** 使用 TensorRT 引擎推理，速度显著快于 CPU。系统检测到 CUDA 环境时默认选中。
- **CPU：** 使用 ONNX Runtime CPU 推理，兼容无 NVIDIA 显卡的机器。

### 6.2 路径设置

| 设置项 | 说明 |
|--------|------|
| 模型路径 | 选择 `.onnx` 或 `.engine` 模型文件 |
| 图片目录 | 待标注的图片（jpg/jpeg/png/bmp）与视频（mp4/avi/mov）所在目录 |
| 输出目录 | LabelMe 标注文件（.json）与原图副本的输出目录 |

### 6.3 检测类别选择

选择模型文件后，程序自动读取模型元数据中的类别信息，并在 **检测类别** 卡片中展示类别列表：

- **类别列表：** 以复选框形式列出模型可识别的所有对象类别（显示格式为 `类别id: 类别名`），勾选状态直观可见。
- **全选/取消全选：** 点击右上角按钮一键切换。当前已全选时按钮显示"取消全选"，点击后清空所有勾选；反之按钮显示"全选"，点击后恢复全部勾选。
- **计数提示：** 列表上方实时显示"已选 X / 共 Y 个类别"。
- **过滤规则：** 只有勾选的类别会被输出到标注文件；全部勾选等价于不过滤。若一个类别都未勾选，点击开始时程序会弹窗提醒，防止误产出空标注。
- **读取失败情形：** 若模型元数据中不含类别信息（列表显示"未提供类别信息"），则不做过滤，检测所有类别。

### 6.4 推理参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| BBox 置信度 | 0.25 | 检测框置信度阈值，越高检出越严格 |
| NMS | 0.7 | 非极大值抑制阈值（重框去重） |
| 关键点置信度 | 0.5 | 仅姿态估计任务显示；低于该值的关键点记为 0 0 0 |
| 抽帧间隔 | 30 | 目录含视频时显示；每隔多少帧抽取一帧 |
| 差异阈值 | 10.0 | 目录含视频时显示；相邻帧差异低于该值的冗余帧自动跳过 |

### 6.5 操作区

- **任务类型：** 目标检测 / 姿态估计 / 实例分割，须与所选模型的训练任务一致。
- **开始标注：** 校验必填项后启动任务，任务期间按钮禁用。
- **停止：** 中断当前任务。
- **导入/导出配置：** 与格式转换页用法相同，标注配置额外包含已选类别列表。

### 6.6 执行与输出

任务运行期间，进度条与日志面板实时显示处理批次、视频抽帧统计等信息。任务完成后，输出目录包含：

- `图片名.json` — 每张图的 LabelMe 格式标注文件；
- `图片名.扩展名` — 原图副本（便于直接在 LabelMe 中打开核对）。

**视频处理说明：** 视频按抽帧间隔抽取关键帧，并自动跳过与前一帧差异过小的冗余帧；抽出的帧作为图片参与批量标注，日志中会统计总抽取帧数与跳过帧数。

## 7. 常见问题（FAQ）

**Q1：界面提示"未检测到 CUDA，仅支持 CPU"？**

GPU 选项被禁用说明 TensorRT 或 CUDA 相关组件不可用。请确认使用的是 GPU 版安装包，且已安装 NVIDIA 显卡驱动。CPU 版安装包不含 GPU 组件，属正常现象。

**Q2：选择 ONNX 模型后长时间无响应？**

首次在 GPU 模式下使用 ONNX 模型时，程序正在后台将模型转换为 TensorRT engine（约 10~30 分钟），日志面板会提示进度，请勿关闭程序。转换完成后会生成同名 `.engine` 文件，之后加载将直接复用。

**Q3：检测类别列表显示"未提供类别信息"？**

所选模型的元数据中不含类别数据。此时不做类别过滤，将检测模型支持的所有类别。如需按类别过滤，请使用带类别元数据导出的 YOLO 系 ONNX 模型。

**Q4：选择 `.engine` 模型后类别列表为空？**

TensorRT engine 文件本身不保存元数据。程序会自动查找同目录下的同名 `.onnx` 文件读取类别；若该文件不存在，则无法提供类别选择。建议 ONNX 与 engine 文件成对保存在同一目录。

**Q5：标注结果中部分类别缺失？**

请检查 **检测类别** 卡片中对应类别是否被勾选。只有勾选的类别才会写入标注文件，可点击"全选"恢复全部类别。

**Q6：GPU 推理速度没有明显提升？**

请确认运行设备选择了 GPU，且模型已转换为 engine（日志中会显示当前使用的模型路径）。首次转换耗时较长属正常现象，后续任务将复用 engine 文件。
